# 실험 설계

기준은 [현재 프로토콜](current-protocol.md)입니다. [2026-09-11 실험](../07-results/sweep-results-20260911.md)에서 42회 재구축으로 전체 372개 점을 측정했습니다. 산포도를 얻기 위해 각 DB + Engine + Index에서 지원하는 검색 파라미터 그리드를 모두 측정합니다.

```text
전체 재구축 반복 3~5회
  회차별 DB 순서 교차
    각 인덱스 구성
      DB 시작 및 자원 제한 검증
      drop → create → vector load → index ready
      그리드의 각 검색 파라미터
        파라미터 적용 → evaluation warm-up
        evaluation measurement
        원시 점 저장 → CSV·집계·산포도 갱신
      DB 중지
```

매회 같은 그리드를 사용합니다. 인덱스 준비 시간과 적재 시간은 같은 재구축을 공유하는 모든 파라미터 행에 기록합니다. 이를 합산해 전체 구축 비용으로 해석하지 않습니다.

기본 300개 query는 기존 SHA-256 층화 분할을 유지합니다. evaluation 200개는 각 파라미터의 워밍업과 측정에 사용합니다. calibration 100개는 Milvus 추가 진단용이며 파라미터를 선택하거나 제외하는 데 쓰지 않습니다. 두 집합의 ID 해시를 저장합니다.

기본 부하는 Top-10, concurrency 10, evaluation 1회 워밍업, 5회 측정 검색입니다. 한 파라미터·한 반복은 1,000개 검색 요청 단위를 최소 5초 이상 반복한 Recall, p50/p95/p99, QPS, CPU·RAM 등을 남깁니다. QPS 타이머는 모든 검색 작업이 끝날 때 닫고 Recall 계산·저장을 제외합니다.

Recall 0.90과 0.95에 도달하더라도 나머지 그리드를 계속 측정합니다. 단조성 보정, 허용 범위 검사, 목표별 대표 후보 선택을 실행 경로에 적용하지 않습니다.

집계는 같은 생성·검색 설정과 데이터·부하 조건끼리 수행합니다. 각 지표의 평균, median, p95/p99, min/max, 표본분산을 원시 반복값과 함께 보존합니다. 산포도는 집계값 대신 **모든 실제 점**을 사용합니다.

Milvus 진단은 각 파라미터의 별도 질의에서 직렬·동시성 검색을 각각 3회 수행합니다. 첫 동시성 표본 대비 편차와 두 모드 median 차이, 상태 수집 결과를 기록합니다. 이 결과로 측정값을 버리거나 구성을 탈락시키지 않습니다.

필터 선택도 1%/10%/50%, 실제 100k/1M 입력, non-synthetic 입력 검증은 전용 스크립트로 같은 프로토콜을 실행합니다. 별도 입력이 없는 확장 결과를 기존 10k 데이터로 대신하지 않습니다.
