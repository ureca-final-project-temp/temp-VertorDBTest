# 비교 결과 해석 기준

비교의 출발점은 [새 실측 372개 보고서](sweep-results-20260911.md)의 **전체 검색 파라미터 Recall–p95 latency 산포도**입니다. Recall@10 0.90과 0.95는 품질 참고선입니다. 목표 주변 허용 구간, PASS/FAIL 또는 구성 제거 기준을 적용하지 않습니다.

## 실제 측정값 비교

| 관점 | 확인할 값 | 해석 |
|---|---|---|
| 검색 품질과 지연 | 전체 evaluation의 actualRecall과 전체 p95LatencyMs | 같은 모집단의 품질·지연을 한 점으로 표시 |
| 검색 폭 변화 | DB·engine·index별 모든 searchParameters | 참고선을 넘기 전후의 점을 모두 보존 |
| 처리량 | 실제 완료한 queryExecutions / 검색 구간 | 동일 입력·동시성 조건에서 비교 |
| 자원 | CPU·RAM 평균/최대, resourceSamples | 해당 검색 구간의 표본과 수집 범위를 함께 확인 |
| 반복 변동 | 같은 생성·검색 파라미터의 3회 재구축 결과 | 평균·median·p95/p99·분산과 개별 점을 함께 확인 |
| 필터 영향 | filtered_* 및 unfiltered_* | 전체 값과 구분해 각 모집단 안에서 비교 |

주 비교 질문은 “Recall 약 0.90 이상에서 어떤 DB·인덱스·검색 파라미터가 더 낮은 latency와 자원을 보이는가”, “약 0.95 이상에서는 어떠한가”입니다. 0.95 참고 수준을 처음 넘는 실제 파라미터를 대표로 선택할 수 있지만, 그보다 낮은 Recall의 관측도 전체 산포도와 원시 자료에 남깁니다.

파라미터가 다른 측정들을 평균 내어 하나의 실제 구성처럼 표시하지 않습니다. 참고 수준에 정확히 일치하지 않는다는 이유로 재측정하거나 값을 보정하지 않습니다. 높은 Recall에 도달한 뒤에도 계획한 전체 그리드를 측정합니다.

## 반복 통계와 자원 해석

개별 점의 p95/p99는 해당 점의 검색 요청 지연에 대한 분위수입니다. 집계의 p95/p99는 같은 파라미터의 세 반복 측정 지표에 대한 분위수입니다. 세 번의 표본으로 넓은 신뢰구간을 보장할 수는 없습니다.

CPU 100%는 한 코어 사용량에 해당합니다. CPU·RAM은 수집 시작과 종료가 모두 검색 구간 안인 Docker 표본에서 계산합니다. 수집 불가인 원시값 -1을 0으로 바꾸거나 저자원 구성으로 해석하지 않습니다. 집계에는 null과 유효 표본 수를 남깁니다. OpenSearch의 RAM에는 미리 확보한 heap이 포함될 수 있습니다.

Exact 정답이 빈 질의는 Recall 평균에서 제외하고 빈 결과 반환 여부를 따로 기록합니다. 실제 정답이 있는 질의의 낮은 Recall은 그대로 기록합니다. Milvus 안정성 진단도 참고 정보이며 산포도 포함 여부를 결정하지 않습니다.

이번 T05 `hnsw_ef=20`은 Recall 0.941237, 0.952062, 0.961340을 관측했습니다. 중앙값은 0.95를 넘지만 세 회차 모두 같은 수준을 보인 것은 아닙니다. 이런 변동을 설명하기 위해 원시 세 점과 고정 파라미터 집계를 함께 제시합니다.

## 과거 판정 필드

[과거 84개 결과](matrix-results-20260911.md)의 targetMet, eligible, passes_* 등은 이전 구현의 산출물입니다. 목표 ±0.01, Recall 하한, latency·RAM 상한을 이용했던 계산은 현재 sweep 프로토콜의 판정 규칙이 아닙니다. 과거 수치는 역사 자료로 보존하며 현재 결과에 해당 필터를 적용하지 않습니다.

## 비교 범위

현재 입력은 10k 합성 벡터입니다. 이 조건에서 얻은 품질·성능·자원 관계를 실제 운영 규모의 순위로 일반화하지 않습니다. 100k/1M, 실제 FAQ·질의, 필터 선택도별 부하, 장애·복구·백업 검증은 별도 실험입니다.

실행 조건은 [현재 실험 프로토콜](../03-benchmark-design/current-protocol.md), 저장·집계 방식은 [결과 형식](../06-implementation/result-format.md)을 확인합니다.
